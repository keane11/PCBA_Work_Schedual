# PCBA 排期工作台

供业务、采购、仓库和工程在局域网内跟踪客户交期、BOM 物料、外协承诺及交付批次。工作台独立运行，与 `pmsys` 使用不同的数据库和端口；它不修改或回写金蝶 KIS，也不修改 `pmsys`。

业务规则、验收场景和当前未定事项见 [PCBA排期工作台_需求草案.md](./PCBA排期工作台_需求草案.md)。接口约定见 [server/API.md](./server/API.md)。

业务、采购、仓库、工程及管理员的实际操作步骤见 [PCBA 排期交付协同平台 V1.0 SOP](./docs/PCBA排期交付协同平台V1.0_SOP.md)，同目录提供可打印的 Word 版。

界面参考了 [Tabler](https://github.com/tabler/tabler) 的管理页信息密度、[Ant Design Pro](https://github.com/ant-design/ant-design-pro) 的企业导航与列表组织方式。工作台继续采用本地静态资源，不依赖这些项目的在线服务；状态色专门用于交期与节点状态，主要业务数据以清晰表格和可直接操作的节点轴呈现。

## Windows 11 启动

1. 在作为主机的 Windows 11 电脑上安装 Python 3.11 或更新版本，确认可从命令行运行 `py -3` 或 `python`。首次运行需能安装 `requirements.txt` 中的依赖。
2. 双击 `start.bat`：首次会安装依赖、立即在后台启动并设置登录后自启动；窗口关闭后工作台继续运行。也可双击 `service.bat` 选择 **2. Install login auto-start and start now**，或在命令行运行 `service.bat install`。
3. 在主机本机打开 `http://localhost:8001` 创建首个管理员账号；空库建管理员不接受其他电脑的局域网请求。其他同事打开 `http://主机电脑名:8001`，在登录页提交个人账号注册申请。管理员到“账号管理”核对姓名、分配业务/采购/仓库/工程角色并批准后，申请人才可登录。管理员也可直接创建账号。替代料审批必须使用工程账号。
4. 以后当前 Windows 用户登录后，工作台会自动在后台启动；主机需保持开机且该用户已登录。双击 `service.bat` 选择 **3. Show status and LAN URL** 可查看状态。后台服务进程异常退出时，守护进程会在约 5 秒后重启。若其他电脑连接失败，以管理员身份运行 `service.bat firewall`，只对专用网络开放 TCP 8001。

`start.bat` 是一键后台启动入口，日常使用不需要保持窗口打开。若需临时在前台查看输出，可运行 `service.bat run`。`service.bat` 还支持 `status|stop|uninstall|backup|firewall`。更新 Python 后端文件后，须在主机项目目录依次运行 `service.bat stop` 和 `service.bat run-bg`，再刷新浏览器；已运行的服务不会自动重载后端代码，单独刷新页面或再次双击 `start.bat` 也不会完成更新。后台运行日志见 `logs/watch.log`、`logs/server.log` 和 `logs/server-error.log`。`pmsys` 的 8000 端口不会被本项目占用。

### 可选：Windows 开机后、用户登录前启动

默认的 `start.bat` 仍采用当前用户登录后自启动。如果主机需要在无人登录时也能提供局域网访问，先在主机上**以管理员身份**打开命令提示符，进入本项目目录并运行 `service.bat install-boot`。它先准备好 Python 环境，再注册名为 `PCBA-Workbench-Boot` 的 Windows 开机计划任务；安装成功后移除当前用户的登录启动项，下一次开机由 `SYSTEM` 账户执行现有的后台启动与守护逻辑。此操作不会由应用自动执行，也不会改变现有数据库。运行 `service.bat status` 可确认任务是否存在、服务是否已启动；要撤销并停止后台服务，运行 `service.bat uninstall-boot`。撤销后若想恢复登录后自启动，双击 `start.bat`。

计划任务模式要求项目目录位于开机即可访问的本地固定磁盘，Windows 的 `SYSTEM` 账户能读写 `data/` 和 `logs/`。该账户通常无法访问需要个人凭据的网络共享备份目录；以后配置镜像备份时，必须先核对运行身份和共享目录权限。启动时若依赖准备、本机备份或 Web 服务启动失败，计划任务会每隔 5 分钟重试，最多 12 次；持续失败后需管理员查看任务计划程序的“上次运行结果”及 `logs/` 并处理原因。首次切换后建议重启主机，确认**无人登录时**另一台电脑能访问，并检查 `service.bat status`、`logs/watch.log` 和备份状态。计划任务负责开机拉起及有限次数的启动失败重试；运行期间由现有守护进程重启异常退出的 Web 服务。

当前局域网入口仍为 HTTP 8001；本次按使用方决定暂不启用 HTTPS。

应用数据保存在本项目的 `data/pcba.db`，日志保存在 `logs/`，虚拟环境在 `.venv/`。这些目录不应随代码更新删除。备份使用 SQLite 在线备份接口以取得一致快照，保存在 `data/backups/`，默认保留最近 30 份。启动前、每天以及执行导入前会备份；管理员还可在页面或用 `service.bat backup` 手动备份。管理员可在页面查看和恢复备份，恢复前会再保存当前数据库。本机备份无法覆盖整机磁盘损坏。

`service.bat status` 和 `GET /api/health` 会根据**实际备份文件**报告本机备份为 `fresh`（36 小时内）、`stale`（超过 36 小时）或 `missing`，同时显示剩余磁盘空间。可用空间不足 1 GiB，或不足当前数据库大小的 3 倍时，`disk_low` 为 `true`；无法读取空间时为 `null`。备份失败时间会保留到下一次成功备份。健康接口中的 `ok` 只表示数据库可查询；不能把 `ok:true` 当作备份已就绪。出现过期、缺失、空间不足或备份失败时，先检查 `logs/backup.log`、`logs/server-error.log` 与磁盘状态，再由管理员手动备份并核对结果。

有第二块磁盘或局域网共享目录后，可在 `server/.env` 设置 `PCBA_BACKUP_MIRROR_DIR=E:\PCBA_Backups` 或 `PCBA_BACKUP_MIRROR_DIR=\\文件服务器\PCBA_Backups`，然后重启服务。每次本机备份完成后，会复制一份到目标位置并校验 SQLite 完整性，两处各保留最近 30 份；**实际运行工作台的账户**须有目标目录写入权限：默认登录启动时为该 Windows 用户，开机计划任务模式为 `SYSTEM`，后者通常不能使用个人账户的网络共享凭据。目标不可用时本机备份仍完成，错误记录在服务日志与 `data/backups/backup_status.json`；`service.bat status` 会显示镜像备份失败，`GET /api/health` 的 `backup.mirror_ok` 会显示 `false`。未设置第二目标时该字段为 `null`，当前仍只有本机备份。

## 账号与权限

注册申请初始状态为“待审批”，管理员批准后才能登录；被拒绝和停用的账号也不能登录。旧版工作台已有账号会保留，原本停用的账号仍停用。管理员可在账号管理中修改姓名、角色、权限和启停状态，并为忘记密码的同事设置新密码。管理员删除账号时须选择进行中工作的接替人、填写原因并输入原登录账号确认；删除后该账号立即失去登录资格，其在跟订单、未完成节点和未确认待办交给接替人。历史操作与原账号名保留用于追溯，原登录账号不能重复注册；当前登录的管理员账号不能删除。每位用户可在登录后修改自己的密码；修改或重置密码会让该账号现有登录失效，需用新密码重登。系统只保存密码哈希，管理员无法查看原密码。同一 IP 在 15 分钟内密码连续错误 10 次，或同一账号错误 25 次，登录接口会暂时返回 429；成功登录会清除该 IP 与账号组合的失败记录。

普通内部账号默认可编辑订单、生产排期、物料采购和待办。数据导入与查看修改记录由管理员单独授权；管理员拥有全部权限。订单和节点仍记录实际操作人、时间及关键变更原因。

## 日常协作与交期核对

“客户订单”按整张订单的所有未完成交付批次提示风险，列表默认风险优先，也可按交期或项目名称排序；搜索、翻页后可继续查看每批的客户要求日、业务承诺日和正式预测偏差。Excel 导出范围由搜索词决定，翻页与排序不会截断导出。“项目排期”和“待办中心”也提供搜索、筛选与分页；待办中的“查看问题”会打开相关订单、批次、板卡节点或物料记录。

风险条件仍存在时，待办不能确认完成；先处理源记录，待系统重算为“条件已恢复”，再由责任人确认。历史上误关闭但条件仍存在的待办会自动重新打开并留下修改记录；转派只能选择已启用且已获批的账号。多人同时修改同一记录时，过期版本会被拒绝，当前表单保留输入并提示重新读取，避免覆盖同事的改动或直接丢失草稿。

## 首次历史数据

用户提供的 JSON 已一次性迁入 8 个项目、88 个节点。项目名称、业务负责人、数量、节点顺序、耗时和日期保留在正常项目排期中；页面不再提供旧版 JSON 导入入口或重复的旧版来源表。以后从“项目排期”新建项目，或在“数据导入”上传 KIS 销售订单 CSV/XLSX/PDF 并逐项确认差异。

这批记录缺少客户、正式订单号、产品编码、BOM 明细、客户交期及外协厂承诺，故使用临时订单号并提示补录。原负责人尚未关联工作台账号时显示姓名与“账号待绑定”；管理员可在“项目排期”批量预览、填写原因后绑定历史业务负责人及各阶段工序负责人。系统先前回退派给管理员的未完成待办会随真实负责人自动改派并留痕，人工转派的待办保留原责任人。项目列表中的节点推算日期基于已录工序计划，不代表客户正式交期或厂商承诺。请逐单核对阶段分类和缺项后再用其判断交期。

首页把“红色风险”“黄色临期”和“交期无法判定”分开显示。没有交付批次、客户要求日、业务承诺日或正式预测依据的项目，可能暂时没有红黄风险，但不会因此被当作已核实安全；“可评估覆盖率”表示未完成项目中资料足以判断交期或研发目标的比例，项目缺项会列出待补原因。纯研发打样依据阶段目标、到板日期和节点计划判断，不要求凭空建立客户交付批次；PP/MP 还需要核对交付批次、生产分配、BOM、可用物料和厂商承诺。

新建单产品订单时可同时填写首批交付数量、客户要求交期、业务承诺交期、人工预计交付日及依据；已全部交付的历史订单可填写实际交付日，并按所选的发货或客户签收口径登记完成。人工预计日只显示为临时估算，正式预测仍由物料、外协厂承诺和物流日期计算。分批交付时，在订单详情分别建立后续交付批次；每批分别记录实际发货或客户签收。旧 JSON 缺少的交期和实际交付日期会保持空白，并在待办中提示补录。

## 按研发、PP、MP 分开排期

同一产品行可分别建立阶段批次，阶段单号、数量和节点各自管理，并在同一项目下按阶段查看。顶层客户订单号与各阶段单号分开保存；研发打样可以先建内部研发项目，进入 PP/MP 后在原项目增加阶段批次，分别填写阶段单号。取得正式客户订单时，可在原项目补齐客户订单号、客户名称并切换为客户订单；原研发记录会保留。旧记录按数量给出阶段建议：20 件及以下建议研发、超过 1000 件建议 MP，其余建议 PP；这是待核对的初始分类，不以数量自动认定实际研发/试产/量产状态。

“项目排期”按项目显示交期目标、BOM 关联、当前节点及阶段批次；问题收在可展开的“待处理事项”中。点击项目名称旁或批次行的“生产节点”可打开点到点进度轴：已完成、当前和待开始一眼可见；11 个节点在常用桌面宽度折返为两行，无需横向滚动即可看全名称、状态和计划日期。点击圆点可直接编辑该节点的负责人、计划与实际日期并勾选完成。完整生产批次也显示同一进度轴。浏览器刷新会保留当前页面、项目筛选、阶段筛选和已打开的节点面板；退出登录后清除这些临时界面状态。

| 阶段 | 主要跟踪内容 | 日期口径 |
| --- | --- | --- |
| 研发试产打样（RD） | 嘉立创打样下单、预计/实际到板、研发焊接调试、功能验证 | 排期起点、内部样机或客户目标日、打样下单日、调试验收日；节点预计日为草案。 |
| PP 试产 | 工程 BOM、齐套与 IQC、我方发料、板厂签收、试产工序与问题关闭 | 阶段起点、板厂承诺开工/完工、阶段目标日；客户要求与业务承诺仍在交付批次单独保存。 |
| MP 量产 | 锁定 BOM、采购齐套、外协生产、检验、回厂/直发和客户交付 | 阶段起点、板厂承诺开工/完工、每批客户要求交期与业务正式承诺交期分别保存。 |

每阶段有独立的产品节点模板。系统按模板耗时和工作日/自然日规则生成初稿，支持 0.5 天、逐节点指定负责人、调整计划与实际日期、增删及上下移动排序。新建批次或修改排期起点时，会按该产品阶段模板、当前公司节假日立即显示“节点草案最早完工”；此结果仍需核对到料和厂商承诺，不是正式客户交期。节点需先指派已启用的工作台账号，勾选“已完成”即记录实际完成日期、操作人和时间；误勾选可填写原因撤销。勾选工序只表示该节点完成，生产批次完工和客户交付仍须分别登记。手工改某节点计划或录入到板日期后，后续未固定节点随之重算；模板和初稿都不等于厂商正式承诺。研发批次录入调试验收日后可完成，纯研发订单无需先伪造客户交付批次。PP/MP 的板厂承诺与客户交付仍按独立字段和批次跟踪。

计划完成日已过、实际完成日仍为空的节点会触发“节点逾期”待办。为避免一个旧批次的多个后续节点同时刷出大量待办，每个生产批次先提示顺序最前面的逾期节点，并在标题汇总其余超期节点。PP/MP 的正式完工预测会变为“无法确定”，另显示按超期工作日顺延的临时估算；负责人更新实际进度、计划并向厂商重新核实承诺后，再按新信息计算。交付批次即使数量已排满，若尚未足额关联生产批次，也会另有“未分配生产”待办并显示缺口数量；它与“订单尚未建立足额交付批次”是两种不同缺项。

## 项目 BOM 关联与逐项核料

1. 在“数据导入 → BOM”分别导入各块板的清单并确认差异。目录按 **BOM 母件编码＋版本** 保存；系统不会凭项目名称自动判断哪些板属于同一客户产品。
2. 在“项目排期”为客户产品配置板卡并确认完整组成。例如 TAV3000 可有主板和按键板，两块板各填板位、板名、BOM 母件编码、默认版本及“每件产品用板数”（1～10000 的正整数）。客户产品编码和客户订单数量仍表示成品套数；两块板可选择不同 BOM 版本。普通单板项目可继续使用原有“关联 BOM”流程。
3. 新建 PP/MP 生产批次后，工作台保存当时的板卡组成快照。逐块板选择目录版本并锁定 BOM；**全部板卡锁定后**，该批才算 BOM 已锁定。目录后续调价或改版不会覆盖已锁定的批次。项目板卡组成修改会取消当前确认，须重新确认；已有批次保留旧快照。仅当批次尚未锁 BOM、没有实际进度时，才可由操作员明确启用最新板卡计划。旧单板批次不会自动转换，已有历史锁定快照保持不变。
4. 在批次“逐项核料”中查看合并后的物料需求。相同物料即使出现在主板和按键板，也按物料编码汇成一条预留与缺口；展开 BOM 来源仍可看到所属板卡和原目录行号。可逐项核对仓库预留、已发料、采购 ETA、到料/IQC、替代料与损耗。
5. “已核对”只表示操作人确认过当时依据，**不表示齐套**。只有合格且已预留/已发的数量计入齐套；BOM、库存、预留、采购或到料依据变化后，该条自动变为“需复核”。页面把核对进度、需复核项与仍有缺口项分别统计。

在项目“管理板卡”中，每个客户产品可选“共用批次节点”或“各板独立排期”，切换时须填写原因。共用模式由一个生产批次统一记录外协厂承诺和工序节点，各板仍分别锁定 BOM。独立模式在同一个成品生产批次下，为每块板分别记录计划生产片数、外协厂、承诺开工/完工日、工序节点和实际完工片数；批次详情和项目节点抽屉按板折叠展示节点，默认只显示摘要；展开单块板后，可分别指定节点责任人、填写计划/实际日期并勾选完成。历史项目和批次默认共用模式。修改项目排期方式只影响新批次；已有批次保留原方式，未锁 BOM 且没有实际进度的批次可由操作员明确启用新板卡计划。旧共用节点及其完成记录不自动复制为各板节点。

多板生产批次数量须为正整数件，并按成品套数计算：若生产批次为 300 套，主板每套 1 块、按键板每套 2 块，则最低需 300 块主板、600 块按键板。独立模式中，板卡计划片数默认等于这个最低数，可增加备损数量；低于最低数时，整批正式预测显示“无法确定”。共用模式每条子件按“批次套数 × 每套用板数 × 单板 BOM 单位用量 ×（1＋损耗率）”计算；独立模式按“该板计划片数 × 单板 BOM 单位用量 ×（1＋损耗率）”计算。两种模式均逐 BOM 行向上取整，再按物料编码合并缺口；仓库预留与采购 ETA 仍按父生产批次的合并物料管理，板级预测保守地使用整批齐套状态。价格逐 BOM 行乘单价、四舍五入到分后求和。任一板未锁定或任一行缺价时，批次完整总价不显示，仅保留已锁且有价部分的参考小计。

独立模式下，每块板的预计完工与实际足额完工分别计算，整批成品的预计完工日取**各板中较晚的日期**。任一必需板缺 BOM、计划片数不足、缺厂商承诺或存在待确认的物料/节点延期时，整批正式日期保持“无法确定”，并列明是哪块板及原因；有依据的临时日期只作参考。各板实际完工片数均达到本批最低需求后，整批才按最晚实际足额完工日判定为生产完成。研发打样项目若采用逐板模式，还须填写调试验收日 `debug_accepted_at` 才能结案；单填验收日、未登记全部必要板足额完工，不会结案。逐板 RD 的板厂日期用于样板目标风险的计划/临时参考，不会冒充正式客户交期。同一外协厂的板级档期重叠会生成核对待办，负责人可填写并行生产依据；相冲突的计划后来改变时，需重新确认。PP/MP 交付预警继续用整批预测与客户要求交期、业务承诺交期分别比较。客户交付批次、生产分配和订单完成量始终按**成品套数**统计，不把各板数量相加当作交付数量。

## Excel 导出

“项目排期”页可导出当前项目和阶段筛选下的 `.xlsx`，包含项目清单、生产批次、板件排期和生产节点；多板独立排期会逐板列出外协承诺、数量及节点责任人。“客户订单”页可按当前搜索词导出客户订单、交付批次和生产交付关联，不包含内部研发项目。两份文件都有“导出说明”页，记录筛选范围与导出时间。单号、批次号和编码按文本保存，打开 Excel 时保留前导零；未确认的正式预测日期留空，原因和临时估算分列显示。

## KIS 导入

人员可按需从 KIS 或其他来源导入小批量 `.csv`、`.xlsx` 和 `.pdf` 单据，包括销售订单、BOM、采购、入库；库存也沿用相同入口。CSV/XLSX 在本机读取；配置密钥后，选中 PDF 会自动调用 DeepSeek，不会在主机运行 OCR 模型。主机把 PDF 页面转为图片发送至 DeepSeek；这是一次联网 API 调用，需有网络和可用额度。AI 结果只是待核对的候选表格，不会自动写入订单或 BOM。调用失败时可重试；文字表格 PDF 也可回退到本机表格解析。界面先检查表头，再由操作者映射到下面的规范字段。PDF 单号、BOM 版本等若只在页眉，可在“PDF 页眉固定字段”填写一次用于该文件每行；表格列有映射时以列值为准。预览逐行显示校验结果、新增/更新/不变和字段差异，操作者逐项选择是否应用。**识别后的单号、物料、数量、日期和价格必须人工核对。**给出的订单 PDF 样本已可预览 4 条有效明细；表外订单号须核对后填入固定字段。给出的 BOM Excel 样本会自动识别第 2 行表头；选择“按母件/子件拆分 → 级次”、填写 BOM 版本，可预览两组母件下 99 条子件及参考材料单价，母件自身不作子件导入。导入的两组母件仍须由人员分别关联到客户产品的板卡，不能仅凭同一个 Excel 文件自动合并。该模式用 Excel 物理行号作为 BOM 行号，源文件重排或插行后须核对匹配差异或启用新 BOM 版本。其他 KIS 导出版式与库存口径仍需脱敏样表核对。

DeepSeek 密钥由管理员将 `server/.env.example` 复制为 `server/.env`，在其中设置 `DEEPSEEK_API_KEY=...`；也可通过同名环境变量设置。浏览器与数据库都不保存密钥。可使用与 `pmsys` 相同的 DeepSeek 账号密钥，但由本项目单独配置，以免工作台依赖另一个系统的安装目录。配置后重启工作台服务。未配置时 AI 解析不可用，CSV/XLSX 和文字表格 PDF 仍可导入。只有选择 PDF 才会发送页面内容；开发验证使用模拟接口，不上传公司的示例订单。

标识符（单号、编码、行号）在 Excel 中应存为文本，以保留前导零。数量使用十进制，日期使用 `YYYY-MM-DD`。未映射的目标字段不会在再导入时覆盖已有手工值。采购 ETA 缺失时保持为空，并提示补日期；库存快照的时间与口径需要人工确认，不能把导入时间当作 KIS 实时库存。`on_hand`（现存量）快照的原数量会保留供核对，但其基数不计入可预留库存或齐套。若现存量含待检、不合格、冻结或其他订单已占用库存，仓库先核实并扣除，再在“数据导入”提交新的 `available`（可用量）快照；原快照和操作记录保留。未经核对的现存量不能用来承诺齐套，相关缺口会提示仓库确认。快照之后单独登记并通过 IQC 的入库量仍按规则计入可用量。

### 通用演示模板

销售订单：`order_no,line_no,customer,product_code,product_name,quantity,due_date,promised_date`

```csv
order_no,line_no,customer,product_code,product_name,quantity,due_date,promised_date
SO-DEMO-001,1,示例客户,PCBA-A,控制板 A,100,2026-10-20,2026-10-18
```

BOM：`product_code,bom_version,source_line_no,material_code,material_name,quantity_per,loss_rate,unit_price`；`unit_price` 为可选人民币单价，缺项可在工作台补录。

```csv
product_code,bom_version,source_line_no,material_code,material_name,quantity_per,loss_rate,unit_price
PCBA-A,V1,1,M-001,电阻,4,2%,0.08
PCBA-A,V1,2,M-002,连接器,1,0,1.50
```

库存：`material_code,quantity,as_of,basis`；`basis` 使用 `on_hand`（仅记录现存量）或 `available`（已核实可用量，才能作为预留基数），需和 KIS 导出定义核对。

```csv
material_code,quantity,as_of,basis
M-001,500,2026-09-28,available
M-002,80,2026-09-28,available
```

采购：`reference,source_line_no,material_code,quantity,eta,order_no,line_no`；`order_no`/`line_no` 为关联销售订单行，不能代替 `source_line_no`（KIS 采购单行号）。

```csv
reference,source_line_no,material_code,quantity,eta,order_no,line_no
PO-DEMO-001,1,M-002,30,2026-10-03,SO-DEMO-001,1
```

入库：`reference,source_line_no,material_code,quantity,received_at,iqc_status,accepted_quantity,order_no,line_no`。实收量不自动等于 IQC 合格量。

```csv
reference,source_line_no,material_code,quantity,received_at,iqc_status,accepted_quantity,order_no,line_no
GR-DEMO-001,1,M-002,20,2026-10-03,pass,18,SO-DEMO-001,1
```

同一采购单、入库单或 BOM 版本中可重复出现同一物料。应映射稳定的 `source_line_no`，此时用单号（BOM 用产品和版本）加源行号标识一行。缺少源行号时，重复物料行会在预览中全部报错，需先明确唯一键，不会自动合并。KIS 采购记录可先作为未分配到生产批次的来源记录保存，实际分配由人员核对。

导入 BOM 后，切到“数据导入 → BOM”可按产品和版本补录目录单价、填写测算生产数量并查看人民币总价；生产批次详情可单独维护已锁定 BOM 快照的单价。每行需求按 `ceil(生产数量 × 单位用量 × (1 + 损耗率))` 取整，行金额四舍五入到分后求和。缺任意单价时只显示已报价小计，总价标为待补齐；目录调价不会改写已锁定批次的价格。

## 范围与限制

- 工作台只核对本系统记录的外协厂承诺档期重叠；厂商未提供完整已占产能，不能据此断言真实产能冲突。
- 仓库在工作台中的库存预留是内部承诺，不同步占用 KIS；导入新的 KIS 库存快照后须重新核对预留缺口。
- 产品 BOM 锁定为生产批次快照；导入新版 BOM 不应自动改写已锁定批次。
- KIS 字段适配和库存口径仍待脱敏导出小样验证。工作日默认周一至周五，管理员维护公司节假日。物料需求目前对每条 BOM 行按整数件向上取整；拿到物料计量精度后须复核。厂商完工到发货、签收的默认估算分别为 1、2 个工作日，可在交付批次调整。

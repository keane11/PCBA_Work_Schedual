# PCBA 排期交付协同平台 V1.0 操作规程（SOP）

| 文件项目 | 内容 |
| --- | --- |
| 文件编号 | PCBA-SOP-001 |
| 版本 / 日期 | V1.0 / 2026-09-29 |
| 适用人员 | 业务、采购、仓库、工程、生产节点责任人、系统管理员 |
| 适用范围 | 当前局域网部署的 PCBA 排期交付协同平台 |

## 1. 目的与使用边界

本规程用于把客户交期、项目阶段、板卡 BOM、物料、外协进度和客户交付放在同一工作台跟踪，及时发现缺项、延期及无人负责的事项。操作人应以单据、厂商确认或实物记录为依据填写日期和数量，并在工作台完成责任闭环。

平台目前**没有与金蝶 KIS 自动同步**。人员从 KIS 导出文件后在“数据导入”中预览、核对和应用；平台的库存预留也不会回写 KIS。平台给出的节点草案和临时估算不等于厂商正式承诺或客户交期。

## 2. 角色与责任

| 角色 | 主要操作与核对责任 |
| --- | --- |
| 业务负责人 | 建立项目或客户订单；维护客户要求日、业务承诺日、交付批次、完成口径和客户签收；处理交期风险。 |
| 采购负责人 | 维护采购单、分批到料与 ETA；向供应商确认预计到货日；处理缺料、退换与补购待办。 |
| 仓库负责人 | 核实库存快照口径和可用量；按生产批次确认预留、发料、到料及 IQC 结果；复核物料缺口。 |
| 工程人员 | 核对板卡组成、BOM 版本和替代料；使用本人工程账号审批替代料并记录依据。 |
| 生产节点责任人 | 核对本人负责的工序计划、实际日期和外协反馈；据实勾选节点完成，处理节点逾期。 |
| 管理员 | 审批账号和权限、维护公司日历、查看备份及必要时恢复、检查服务和日志。 |

普通内部账号可按已授予权限编辑业务数据，系统记录实际修改人。数据导入和查看修改记录需管理员单独授权；替代料审批限工程账号；只有待办当前责任人或管理员可确认待办完成。

## 3. 必须区分的日期与状态

| 名称 | 使用口径 |
| --- | --- |
| 客户要求交期 | 客户提出的交付日期，单独保留和预警。 |
| 业务承诺交期 | 我方正式向客户承诺的日期，单独保留和预警；变更须填写原因。 |
| 厂商承诺开工 / 完工 | 外协厂确认的生产日期；板卡独立排期时逐板填写。 |
| 节点计划 / 实际日期 | 某道工序的计划与实际，不自动代表整批完工。 |
| 正式预测 | 在 BOM、物料、厂商承诺等依据完整时由系统计算；缺依据时显示“无法确定”。 |
| 临时估算 | 人工预计或按延期天数顺延的参考日期，须与正式预测分开阅读。 |
| 交付完成 | 按该订单选择的“发货”或“客户签收”口径，逐交付批次登记实际数量和日期。 |

“红色风险”表示预测延期或交期已逾期；“黄色临期”表示距离交期不超过 5 个公司工作日。**没有红黄提示不等于安全**：还须检查“无法确定”、缺项和待办。工作日默认周一至周五，管理员维护节假日及调休。

## 4. 首次使用与日常登录

1. 主机 Windows 11 已部署时，双击项目目录中的 `start.bat`。首次启动会准备依赖、后台运行并设置当前 Windows 用户登录后自启动；日常使用不必保持命令窗口打开。
2. 首位管理员在主机本机打开 `http://localhost:8001`，按“首次使用：在本机创建管理员”建立账号。密码至少 10 位。
3. 其他人员在浏览器打开 `http://主机电脑名:8001`，点“申请注册”并提交姓名、账号和密码。管理员在“设置与备份 → 待审批申请”核对身份、选择角色和权限，批准后方可登录。管理员也可在“内部账号”直接创建账号。
4. 每人只用本人账号操作；离岗时退出。忘记密码由管理员在账号管理中重置；登录后的用户可“修改我的密码”。密码修改后需重新登录。人员离职或账号不再使用时，由管理员在“设置与备份 → 内部账号”点击“删除”，核对待交接数量，选择接替人、填写原因，并输入原登录账号确认。删除会立即撤销该账号的登录会话，将在跟订单、未完成节点和未确认待办移交接替人；历史记录保留，原登录账号不能再注册。
5. 每天进入“交付总览”查看红色风险、黄色临期、无法确定及待办；再按顶部“当前项目”或“项目排期”进入负责项目。

## 5. 标准业务流程

### 5.1 建立项目、产品与订单

1. 在“项目排期”点击“+ 新建项目”。选择“内部研发”或“客户订单”，填写项目名称、产品、数量和业务负责人。内部研发尚无正式销售单时可先建项目，取得正式订单后再在订单详情补客户及正式订单号。
2. 客户订单应填写客户订单号、客户名称及产品信息。若有首批交付，同时填写首批数量、**客户要求交期**、**业务承诺交期**；人工预计交付日须填写依据。两种正式交期都保留，不能用预计日替代。
3. 一张订单有多次交货时，到“客户订单 → 查看订单”分别建立交付批次，逐批填写数量、两种交期及该单的交付完成口径。核对各批数量之和；未建立足额批次会产生待办。
4. 同一项目的研发打样、PP、MP 分别建立阶段生产批次；各阶段单号和数量可不同。生产批次与客户交付批次分开记录，不能把生产数量直接当成已交付数量。

### 5.2 配置板卡与导入 BOM

1. 一个客户产品有主板、按键板等多块板时，在项目或订单详情点“配置多板 / 管理板卡”→“+ 添加板卡”。逐板填写板位、板名、BOM 母件编码、默认版本及“每件产品用板数”，核对后点“确认板卡组成”。
2. 按业务实际选择“共用批次节点”或“各板独立排期”。前者共用一套工序和厂商承诺；后者逐板管理计划片数、厂商、承诺日期、节点与实际完工片数。修改排期方式只影响后续新批次；已有批次须按页面条件另行更新。
3. 在“数据导入 → BOM”导入各板 BOM，核对“母件编码＋版本”、子件、单位用量、损耗和单价。一个表含多个母件时，按“级次”拆分并逐一核对归属；导入完成不会自动把多块板归到同一项目。
4. 在“数据导入 → BOM → BOM 单价与总价”补目录缺价、填写测算生产数量并查看 CNY 小计和总价。缺任一单价时完整总价显示待补齐。目录价格与后续锁定的批次价格分别维护，改单价应填写原因。

### 5.3 建立阶段排期与维护生产节点

1. 在订单详情点击“+ 建立生产批次”，选择研发打样、PP 或 MP，填写阶段单号、数量、排期起点和日历规则。PP/MP 继续填写外协厂承诺开工、完工日期；研发打样填写打样目标、预计及实际到板、调试验收等适用信息。
2. 在“启用板卡 / 逐板 BOM”为每块板选择目录中的正确版本并“选择并锁定 BOM”；普通单板项目使用“关联 BOM / 锁定 BOM”。全部必需板卡锁定后，该批次才算 BOM 锁定。锁定的是本批次快照，后续导入或目录调价不会自动覆盖；批次的“BOM 物料成本”可单独补价。
3. 系统按该产品阶段模板和默认耗时给出“节点草案最早完工”。此日期仅用于核对计划；责任人应结合物料齐套、厂商承诺和实际进度逐节点调整。可保存产品模板供后续同类批次使用。
4. 在“项目排期”点击项目名称或批次的“生产节点 / 逐板节点”，查看点到点进度轴。点击节点圆点直接修改负责人、耗时、计划开始/完成、实际开始/完成及备注。
5. 收到工序完成依据后，先选有效的节点责任人账号，再在节点编辑框勾选“已完成”。未填实际完成日期时系统记当日；日期误填或撤销完成必须填写原因。**节点打钩仅表示该工序完成**，还须另行登记生产批次或板卡完工及客户交付。
6. 独立板卡排期应逐板填写计划片数和外协承诺、维护节点并登记实际完工片数。每块板至少达到“生产成品套数 × 每套用板数”；不足时整批正式完工无法确定。整批预测按必需板卡中较晚的完工日判断。
7. 发现同一外协厂档期重叠时，向厂商核对是否能并行；能并行才在冲突提示中填写联系人、日期及依据。厂商计划改变后重新核对。

### 5.4 逐项核料、采购、仓库与 IQC

1. 在“物料齐套 → 逐项核料”选项目和生产批次。逐条打开“逐项核对”，核对 BOM 需求、合格预留、已发料、缺口、采购 ETA、到料和 IQC。不同板使用同一物料时，系统按物料编码合并缺口，来源仍可展开查看。
2. 仓库导入库存时标明快照日期及口径：“现存量”只是原始数量，不能直接作为可预留量；核实已占用、待检等后，再提交“可用量”快照。工作台内的仓库预留是内部承诺，不占用 KIS 库存；新快照到来后复核原预留和缺口。
3. 仓库按订单确认预留数量，收到物料后登记到料并填写 IQC 合格数。不合格或部分合格时据实记录；系统重算缺口，采购处理补购或退换待办。未检合格的数量不能当作齐套。
4. 采购登记采购单及 ETA，并注明“人工估算 / KIS 日期待确认”或“供应商已确认”。未指向生产批次的采购记录须“分配到生产批次”，其 ETA 才参与该批次齐套估算。无 ETA 或仅估算时正式预测可能仍为“无法确定”。
5. 如需替代料，由人员提交申请，工程人员用本人账号审批并记录验证依据。批准后仓库仍须预留合格替代料，才能计入齐套。损耗率按物料或订单核对后在工作台调整。
6. 每条物料核完可点“确认已核对并继续”。“已核对”仅代表当时依据已查，不代表齐套；BOM、库存、预留、采购或到料依据变化后，按“需复核”重新检查。

### 5.5 发料、外协与客户交付

1. 在生产批次记录我方发料、厂商签收、厂商完工及成品回厂或直发，填写实际日期、数量和依据；独立排期按板登记完工片数。
2. 在交付批次用“关联数量”把生产批次的成品套数分配给客户交付批次。一个生产批次可对应多次交付，不能重复分配同一数量；未足额关联会出现待办。
3. 业务按选定的完成口径在交付批次“记录发货 / 签收”，逐次登记数量和实际日期。发货口径以发货完成，签收口径以客户签收完成；不得把厂商完工或节点完成直接记为客户已交付。
4. 交付前分别核对客户要求日、业务承诺日与正式预测；若正式预测为“无法确定”，先补齐缺项并向外协厂重新确认，临时估算不能作为对客户的正式交期。

## 6. 预警与待办闭环

1. 每个工作日先处理“交付总览”的红色风险和“无法确定”，再看黄色临期；进入“待办中心”查看本人待办和项目“待处理事项”。
2. 对缺 BOM、缺日期、缺 ETA、库存待确认、物料不足、节点逾期、厂商档期冲突等事项，先修改对应业务记录，再复核风险和预测。物料晚到、节点逾期时，联系厂商更新承诺；系统显示的顺延日期仅为临时估算。
3. 待办需转交他人时点“转派”，选新责任人并填交接说明。处理完毕后当前责任人或管理员点“确认完成”，写明结果及依据。
4. 风险条件消失会自动取消红黄预警；待办仍须责任人确认。确认待办也不会掩盖仍存在的风险。修改记录中可追溯操作人、前后值、时间与原因。

## 7. 文件导入与 Excel 导出

### 7.1 KIS 或其他来源的导入

1. 从 KIS 按需导出销售订单、BOM、库存、采购记录或入库记录；在“数据导入”选择相应类型及 `.csv`、`.xlsx` 或 `.pdf` 文件。目前这一步由人员操作，**不是 KIS 自动同步**。
2. 确认工作表、表头行和列名映射；PDF 的单号、BOM 版本等若只在页眉，核对原件后填“PDF 页眉固定字段”。库存还要填写快照日期和“现存量 / 可用量”口径。
3. 点“预览差异”，逐行核对单号、物料编码、数量、日期、价格，以及“新增 / 更新 / 不变 / 错误”。只选择确认无误的行和差异字段；修改关键数量、日期或价格时填原因，然后“应用所选更改”。有错误的行先修正，不以整单成功代替逐项检查。
4. 选中 PDF 且主机已配置 DeepSeek 时，平台会自动把 PDF 页面图片发送至 DeepSeek 生成候选表格；**不会自动写入业务数据**。AI 新增行默认不勾选，须对照原 PDF 逐项选择。未配置密钥时可使用 CSV/XLSX 和可解析的文字表格 PDF。
5. 导入前系统自动备份。导入完成后检查导入记录、目标订单或 BOM、物料数量及待办变化；源文件重复物料行需有稳定源行号，避免误合并。

### 7.2 导出与对账

1. “项目排期”可按当前项目、阶段筛选导出项目排期 Excel，也可导出全部项目；内容包括项目、生产批次、板件排期和节点。
2. “客户订单”可按当前搜索条件导出客户订单 Excel，也可导出全部客户订单；内容包括交付批次及生产交付关联，内部研发项目不在客户订单导出中。
3. Excel 是导出时的快照。对外发送前由业务负责人核对客户、数量、日期及“正式预测 / 临时估算”列；不要把临时估算当成正式承诺。

## 8. 管理员维护与故障处理

| 事项 | 标准操作 |
| --- | --- |
| 账号与权限 | “设置与备份 → 内部账号”审批、启停、修改角色/权限、重置密码或删除账号；删除前核对接替人和工作交接，工程替代料审批须保留工程角色。 |
| 公司日历 | “设置与备份”维护节假日与调休，变更后复核相关节点和交期计算。 |
| 服务状态 | 在主机双击 `service.bat`，选“3. Show status and LAN URL”；确认健康状态与局域网地址。服务在当前 Windows 用户登录后自启动，主机须保持开机且该用户已登录。 |
| 本机备份 | “设置与备份 → 立即备份”，或 `service.bat` 菜单选“4. Make a consistent SQLite backup now”。系统启动前、每天及应用导入前也会备份；本机默认保留最近 30 份。 |
| 恢复备份 | 管理员在“设置与备份”选择备份并输入“恢复”；系统先另存当前数据库，再替换并要求重新登录。恢复后核对关键订单和交期。 |
| 本机打不开 | 运行 `service.bat status`，检查 `logs/watch.log`、`logs/server-error.log`；必要时双击 `start.bat` 启动。 |
| 同事打不开但主机可用 | 核对主机名及 Windows 专用网络；管理员权限运行 `service.bat firewall` 放行 TCP 8001。 |

数据库在 `data/pcba.db`，本机备份在 `data/backups/`。当前未配置第二备份目标时，备份只在主机本地；若以后设置第二磁盘或共享目录，按 `README.md` 配置 `server/.env` 的 `PCBA_BACKUP_MIRROR_DIR` 并检查状态。不要在更新程序时删除 `data/`、`logs/` 或 `.venv/`。

## 9. 每日交接检查表

| 时点 | 检查动作 | 完成标准 |
| --- | --- | --- |
| 每日开始 | 查看交付总览、本人待办、负责项目的缺项和生产节点。 | 红色与无法确定事项已指定责任人；黄色临期有跟进计划。 |
| 采购 / 仓库有变化时 | 更新 ETA、到料与 IQC、库存可用量、预留和发料；复核“需复核”物料。 | 数量、日期、来源和责任人有记录，缺口重新计算。 |
| 收到外协反馈时 | 更新厂商承诺、节点实际日期和完工数量；核对冲突及顺延估算。 | 逾期节点有处理依据；正式预测与临时估算分开。 |
| 发货或签收后 | 登记交付批次实际数量及日期，核对订单剩余量和待办。 | 所选完成口径下的交付量正确，无重复计数。 |
| 每日结束 | 责任人确认已解决待办；管理员按需检查服务与最近备份。 | 未关闭事项有下一步、责任人和可追溯依据。 |

## 10. V1.0 验收与使用限制

- 项目可含多块板，BOM 按板关联并锁定到生产批次；客户交付数量按成品套数统计，不把板片数相加。
- 研发打样可只用内部目标和调试验收管理；PP、MP 仍须核对厂商承诺、物料齐套和客户交付批次。
- 平台只发现**本系统已记录**的同厂档期重叠，不能代表外协厂全部已占产能。
- 新导入的 KIS 库存快照可能改变可用量依据，仓库须重新核对工作台预留；两系统之间不会自动占库。
- BOM 物料需求按每行整数件向上取整，价格按行计价到分；具体计量精度和采购价格以核实的业务单据为准。
- 当前入口为局域网 HTTP 8001；需要第二备份目录或其他网络入口时，由管理员按部署说明另行配置。
